# Лекция 2. Демонстрация C# в IDE

Конспект для преподавателя к практическому показу после лекции «C# для разработки приложений». Формат каждого раздела: цель, действия в IDE, готовый код с комментариями, ожидаемый вывод и пояснение. Основной маршрут рассчитан на 90 минут; базовые переменные, условия и циклы студентам уже знакомы.

Общий пример — приложение новостей: заголовок и текст, объект новости, изменение заголовка, подписка на событие, получение данных через `Task`, отбор новостей и обработка неверного ввода. Материал согласован с текущими 26 слайдами второй лекции. `event` и `Task` получают отдельные демонстрации.

## Как пользоваться примерами

Каждый блок C# ниже самодостаточен: его можно целиком поместить в `Program.cs` подготовленного консольного окружения .NET 10 и запустить. При переходе к другой теме заменять содержимое файла целиком. Повторяющиеся определения `NewsArticle` сокращены под конкретную тему; склеивать все блоки в один файл не нужно.

Используются инструкции верхнего уровня. Выполняемые строки идут до объявлений классов и интерфейсов. В асинхронных примерах допустим `await` на верхнем уровне: компилятор формирует соответствующую точку входа. `using` уже включены в каждый блок. В примерах с nullable-ссылками анализ явно включён через `#nullable enable`.

Готовая демонстрация, которая уже лежит в материалах лекции, остаётся отдельным вариантом для показа целого приложения. Этот конспект разбирает небольшие фрагменты по одному. Исходные презентация и проект не требуют правок для чтения конспекта.

Все новости вымышлены. Строки с `example.org` служат учебными адресами и не вызывают сетевых запросов. `Task.Delay` имитирует ожидание без сервера.

## Подготовка до занятия

1. Проверить консольное окружение C# в выбранной IDE и окно Run/Debug. Для приведённых примеров достаточно .NET SDK 10.
2. Увеличить шрифт редактора и консоли. Подготовить точки останова и переключение между редактором и выводом.
3. Перед показом каждого раздела переносить весь его блок кода, включая `using` и определения типов.
4. Преднамеренные ошибки оставлены в комментариях. Раскомментировать одну строку для диагностики, затем вернуть рабочий вариант.
5. Для `event` поставить breakpoint в обработчике. Для `Task` — на вызове асинхронного метода и на строке после `await`.

> [!tip] Ритм демонстрации
> Сначала предложить предсказать результат, затем запустить, после этого сделать одну небольшую правку. Вопросы и изменения кода относятся к демонстрационной части занятия. Теоретический доклад остаётся отдельной частью.

## 01. Точка входа, типы и переменные

**Время:** 05–10 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=2|2]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=3|3]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Узнать точку входа, статические типы, вывод типа через var и интерполяцию строк.

### Действия преподавателя

1. Начать с `Console.WriteLine("Hello, C#!")`, запустить и показать окно вывода. Затем заменить строку готовым примером ниже.
2. Показать `string`, `int`, `bool`. Навести курсор на `titleLength`: IDE определяет `int`, хотя в объявлении стоит `var`.
3. Временно раскомментировать присваивание строки в `titleLength`, прочитать диагностику и вернуть комментарий.
4. Поставить breakpoint перед выводом заголовка. В Debug показать значения `previewLength` и `hasImage`.

### Готовый пример

```csharp
using System;

// Это инструкции верхнего уровня: компилятор создаст для них точку входа.
string title = "УрФУ: библиотека";
string imageUrl = "https://example.org/1.jpg";
int previewLength = 12;
// Проверяем наличие строки с адресом; сетевого запроса здесь нет.
bool hasImage = imageUrl.Length > 0;

// var выводит тип Int32 из Length, но тип переменной остаётся статическим.
var titleLength = title.Length;
previewLength += 3;
// titleLength = "много"; // Ошибка компиляции: здесь ожидается int.

Console.WriteLine(title);
Console.WriteLine($"Длина заголовка: {titleLength}");
Console.WriteLine($"Лимит анонса: {previewLength}");
Console.WriteLine($"Есть адрес картинки: {hasImage}");
```

### Ожидаемый вывод

```text
УрФУ: библиотека
Длина заголовка: 16
Лимит анонса: 15
Есть адрес картинки: True
```

### Что объяснить

В примере использованы инструкции верхнего уровня: не нужно вручную писать `Program.Main`. Компилятор создаёт точку входа. В готовой демонстрации из материалов лекции та же роль записана явно через `Main`.

`var` выводит тип при компиляции и не позволяет затем присвоить значение несовместимого типа. При этом локальную переменную, объявленную через `var`, можно переприсваивать. В интерполированной строке `$"...{выражение}..."` выражения вычисляются перед выводом.

`imageUrl` содержит адрес как обычный текст. Ни присваивание строки, ни проверка её длины не загружают изображение. Для этих учебных данных не нужен интернет.

**Вопрос:** можно ли заменить `previewLength += 3` на `previewLength = "15"`? **Ответ:** нет, тип переменной — `int`, а справа строка.

## 02. Условия, for и foreach

**Время:** 10–15 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=4|4]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Сопоставить условие, цикл со счётчиком и перебор элементов.

### Действия преподавателя

1. Запустить код. Сначала разобрать `if`, затем три части заголовка `for`.
2. Поставить breakpoint внутри `for` и показать значения 1, 2 и 3. Отдельно указать, когда выполняется `number++`.
3. Сравнить с `foreach`: очередной элемент уже доступен в `item`, отдельный индекс не нужен.
4. Заменить `title` на пустую строку, а затем на три пробела. Показать, что `Length > 0` пропускает строку из пробелов. Вернуть исходное значение.

### Готовый пример

```csharp
using System;

string title = "УрФУ: библиотека";
// if выполняет блок только при истинном условии.
if (title.Length > 0)
{
    Console.WriteLine(title);
}

// Начальное значение; условие продолжения; изменение счётчика.
for (int number = 1; number <= 3; number++)
{
    Console.WriteLine($"Новость {number}");
}

string[] titles = { "Библиотека", "Лаборатория" };
// foreach получает очередной элемент: вручную вычислять индекс не нужно.
foreach (string item in titles)
{
    Console.WriteLine(item);
}
```

### Ожидаемый вывод

```text
УрФУ: библиотека
Новость 1
Новость 2
Новость 3
Библиотека
Лаборатория
```

### Что объяснить

`for` удобен, когда нужен счётчик или управляемый шаг. `foreach` подходит для последовательного обхода элементов. Условия и тела циклов выполняются последовательно; ни один из этих циклов сам по себе не делает работу параллельной.

Проверка непустой строки и проверка осмысленного заголовка — разные задачи. Позже будем использовать `string.IsNullOrWhiteSpace`, которая учитывает и пробельные символы.

**Вопрос:** что изменится при `number < 3` вместо `number <= 3`? **Ответ:** будут выведены только новости 1 и 2.

## 03. Преобразования и TryParse

**Время:** 15–21 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=5|5]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Различить числовое преобразование, разбор строки и проверку переполнения.

### Действия преподавателя

1. Перед запуском попросить предсказать результаты `(int)2.8` и `(int)-2.8`.
2. Показать неявное преобразование `int` в `double`. Тип исходной переменной `newsCount` при этом не меняется.
3. Проследить одновременно возвращаемый `bool` и выходной параметр `out` у двух вызовов `TryParse`.
4. Выполнить `checked` и переход в `catch`. Если времени мало, назвать этот участок заранее подготовленной иллюстрацией исключения; подробный разбор будет в конце.

### Готовый пример

```csharp
using System;

int newsCount = 3;
double countAsDouble = newsCount; // Неявное числовое преобразование.
double readingMinutes = 2.8;
// Явное преобразование отбрасывает дробную часть, а не округляет.
Console.WriteLine((int)readingMinutes);
Console.WriteLine((int)-2.8);
Console.WriteLine(countAsDouble);

// TryParse разбирает текст; out получает число, а bool сообщает об успехе.
bool parsed = int.TryParse("12", out int length);
Console.WriteLine($"Корректный ввод: {parsed}, число: {length}");
bool invalidParsed = int.TryParse("двенадцать", out int invalidLength);
Console.WriteLine($"Неверный ввод: {invalidParsed}, число: {invalidLength}");

try
{
    double tooLarge = (double)int.MaxValue + 1;
    // checked делает выход за диапазон int явной ошибкой.
    Console.WriteLine(checked((int)tooLarge));
}
catch (OverflowException)
{
    Console.WriteLine("Число не помещается в int");
}
```

### Ожидаемый вывод

```text
2
-2
3
Корректный ввод: True, число: 12
Неверный ввод: False, число: 0
Число не помещается в int
```

### Что объяснить

Преобразование дробного числа в `int` в показанном диапазоне усекает дробную часть к нулю. Оно не равно округлению до ближайшего целого. `checked` позволяет явно получить `OverflowException`, когда значение не помещается в целевой тип.

Строка `"12"` требует разбора, а не приведения `(int)`. `TryParse` возвращает признак успеха и отдельно записывает число. При неудаче `out` равен нулю, но это не означает, что пользователь ввёл корректный ноль. Положительность длины анонса проверяется отдельно.

**Вопрос:** `TryParse("0", out ...)` успешен? **Ответ:** да. Формат числа корректен, но правило «длина больше нуля» он не проверяет.

## 04. Класс, свойства и методы новости

**Время:** 21–29 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=6|6]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=7|7]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=8|8]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=12|12]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Объединить данные новости в объект и менять состояние через метод с проверкой.

### Действия преподавателя

1. Показать верхние строки использования объекта, затем объявление `NewsArticle`. Сначала найти конструктор и свойства.
2. Временно раскомментировать прямое присваивание `Title` и показать ограничение `private set`.
3. Поставить breakpoint внутри `RenameTitle`. Пройти проверку, `Trim` и присваивание. Обратить внимание на пробелы во входном аргументе.
4. Поставить breakpoint в `GetPreview`, вызвать длины 12 и 100. Показать `Math.Min`, исходный `Text` и возвращаемую строку.

### Готовый пример

```csharp
using System;

var article = new NewsArticle("УрФУ: библиотека", "Открыт новый зал.");
Console.WriteLine(article.Title);
article.RenameTitle("  Новый зал  ");
Console.WriteLine(article.Title);
Console.WriteLine(article.GetPreview(maxLength: 12)); // Именованный аргумент.
Console.WriteLine(article.GetPreview(100));
// article.Title = ""; // Внешний код не имеет доступа к private set.

class NewsArticle
{
    public string Title { get; private set; } = string.Empty;
    public string Text { get; } // Значение задаётся в конструкторе.

    public NewsArticle(string title, string text)
    {
        // И создание, и переименование используют одно правило заголовка.
        RenameTitle(title);
        if (string.IsNullOrWhiteSpace(text))
            throw new ArgumentException("Нужен текст", nameof(text));
        Text = text;
    }

    public void RenameTitle(string title)
    {
        // Сначала проверяем аргумент; при ошибке старое состояние сохранится.
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("Нужен заголовок", nameof(title));
        Title = title.Trim();
    }

    public string GetPreview(int maxLength)
    {
        if (maxLength <= 0)
            throw new ArgumentOutOfRangeException(nameof(maxLength));
        // Анонс не должен выходить за границы исходной строки.
        int length = Math.Min(Text.Length, maxLength);
        return Text.Substring(0, length);
    }
}
```

### Ожидаемый вывод

```text
УрФУ: библиотека
Новый зал
Открыт новый
Открыт новый зал.
```

### Что объяснить

`new` создаёт экземпляр, конструктор задаёт его начальное состояние. `Title` доступен для чтения снаружи, но setter скрыт. Поэтому внешний код изменяет заголовок через `RenameTitle`, где сосредоточено правило проверки.

`RenameTitle` возвращает `void` и меняет объект. `GetPreview` возвращает `string`, а исходный текст сохраняет. `maxLength: 12` — именованный аргумент: его имя относится к параметру метода.

Модель здесь сокращена до `Title` и `Text`. В материалах лекции полная модель содержит также `ImageUrl` и событие, которое отдельно разберём ниже. `Substring` годится для данного простого текста; сложные символы и эмодзи требуют учёта границ текстовых элементов.

**Вопрос:** почему после `GetPreview(12)` полный текст новости остаётся прежним? **Ответ:** метод возвращает отдельную строку и ничего не присваивает свойству `Text`.

## 05. Ссылки, null и безопасный доступ

**Время:** 29–34 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=9|9]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Увидеть общий объект за двумя ссылками и корректно обработать отсутствие выбранной новости.

### Действия преподавателя

1. До запуска спросить, сколько объектов создано. Найти единственный `new NewsArticle`.
2. В отладчике сравнить `article` и `selected`. Выполнить переименование через `selected` и увидеть изменившийся `article.Title`.
3. Присвоить `selected = null`. Показать, что `article` по-прежнему доступен.
4. Разобрать `?.` и `??`. При отдельном показе ошибки раскомментировать строку с `selected!.Title`, запустить и показать `NullReferenceException`; затем вернуть комментарий.

### Готовый пример

```csharp
#nullable enable
using System;

var article = new NewsArticle("УрФУ: библиотека");
// Копируем ссылку, а не создаём второй экземпляр новости.
NewsArticle? selected = article;
Console.WriteLine(ReferenceEquals(article, selected));
selected.RenameTitle("Новый зал");
Console.WriteLine(article.Title);

selected = null; // Убрали одну ссылку; article всё ещё ссылается на новость.
// ?. не обращается к свойству при null; ?? подставляет запасной текст.
Console.WriteLine(selected?.Title ?? "Не выбрана");
Console.WriteLine(article.Title);
// Console.WriteLine(selected!.Title); // ! подавит предупреждение, но не предотвратит NRE.

class NewsArticle
{
    public string Title { get; private set; } = string.Empty;
    public NewsArticle(string title) => RenameTitle(title);

    public void RenameTitle(string title)
    {
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("Нужен заголовок", nameof(title));
        Title = title.Trim();
    }
}
```

### Ожидаемый вывод

```text
True
Новый зал
Не выбрана
Новый зал
```

### Что объяснить

Присваивание переменной ссылочного типа копирует ссылку. `ReferenceEquals` отвечает, ссылаются ли переменные на один объект. Обнуление одной переменной не удаляет объект, доступный через другую.

`NewsArticle?` описывает возможность отсутствия значения. В C# nullable-аннотации ссылок помогают анализу компилятора и обычно порождают предупреждения, а не отдельную защиту времени выполнения. Директива `#nullable enable` явно включает этот анализ для примера.

`?.` пропускает обращение при `null`, `??` даёт запасное значение. Постфиксный `!` лишь подавляет предупреждение nullable-анализа и не выполняет проверку. Это отличается от оператора Kotlin `!!`, который делает проверку с исключением.

**Вопрос:** создаёт ли `selected = article` независимую копию новости? **Ответ:** нет, обе переменные ссылаются на один экземпляр.

## 06. Наследование, is, as и приведение

**Время:** 34–40 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=10|10]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=11|11]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Разделить тип переменной, фактический тип объекта и выбор переопределённого метода.

### Действия преподавателя

1. Показать объявление `NewsArticle article = new VideoNewsArticle(...)`. В Debug зайти в конструктор и проследить `base`.
2. Вызвать `GetContentKind` через базовую ссылку. Объяснить, почему получается «Видео».
3. Сравнить `is VideoNewsArticle video`, `as VideoNewsArticle` и явное приведение в скобках.
4. Показать `ReferenceEquals` после успешного приведения и обработанное исключение при попытке превратить обычную новость в видеоновость.

### Готовый пример

```csharp
#nullable enable
using System;

// Тип переменной — базовый класс, фактический объект — VideoNewsArticle.
NewsArticle article = new VideoNewsArticle("Репортаж", "https://example.org/video");
Console.WriteLine(article.Title);
Console.WriteLine(article.GetContentKind()); // Будет вызван override.

// Проверяем тип и сразу получаем переменную нужного типа.
if (article is VideoNewsArticle video)
    Console.WriteLine(video.VideoUrl);

var casted = (VideoNewsArticle)article;
Console.WriteLine(ReferenceEquals(article, casted)); // Приведение не копирует объект.

NewsArticle textArticle = new NewsArticle("Текстовая новость");
VideoNewsArticle? missingVideo = textArticle as VideoNewsArticle;
Console.WriteLine(missingVideo is null); // as вернёт null при несовместимости.
try
{
    var wrong = (VideoNewsArticle)textArticle; // Явное приведение вызовет исключение.
    Console.WriteLine(wrong.VideoUrl);
}
catch (InvalidCastException)
{
    Console.WriteLine("Обычная новость не стала видеоновостью");
}

class NewsArticle
{
    public string Title { get; }
    public NewsArticle(string title) => Title = title;
    public virtual string GetContentKind() => "Текст";
}

class VideoNewsArticle : NewsArticle
{
    public string VideoUrl { get; }
    // base инициализирует общую часть объекта через конструктор NewsArticle.
    public VideoNewsArticle(string title, string videoUrl) : base(title)
        => VideoUrl = videoUrl;
    public override string GetContentKind() => "Видео";
}
```

### Ожидаемый вывод

```text

True

```

### Что объяснить

Переменная базового типа может ссылаться на объект производного класса. `virtual` и `override` позволяют выбирать реализацию метода по фактическому объекту. `base(...)` вызывает конструктор базовой части этого же объекта.

`is` проверяет тип и в данном шаблоне даёт подходящую переменную. `as` для показанного ссылочного типа возвращает `null` при несовместимости. Явное приведение бросает исключение при несовместимом ненулевом объекте. Успешное приведение не создаёт новый экземпляр и не меняет тип самого объекта.

## 07. Лямбды, Action и Func

**Время:** 40–46 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=13|13]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Отделить создание делегата от вызова и передать действие в метод.

### Действия преподавателя

1. Поставить breakpoint перед `showTitle(article)`. Выполнить присваивания `Action` и `Func` и убедиться, что в консоли пока ничего нет.
2. Вызвать `showTitle`: теперь выполнится тело лямбды.
3. Вызвать `getTitle`, показать возвращённую строку и её отдельный вывод.
4. Зайти в `ShowArticle`: метод получает действие как параметр и сам выбирает момент вызова.

### Готовый пример

```csharp
using System;

var article = new NewsArticle("УрФУ: библиотека");
// Action принимает новость и не возвращает значение. Пока создаём делегат, не вызываем его.
Action<NewsArticle> showTitle = n => Console.WriteLine(n.Title);
// У Func последний параметр типа — результат, здесь string.
Func<NewsArticle, string> getTitle = n => n.Title;

showTitle(article); // Только теперь выполнится тело первой лямбды.
string title = getTitle(article);
Console.WriteLine(title);
ShowArticle(article, showTitle); // Передаём действие как аргумент.

static void ShowArticle(NewsArticle article, Action<NewsArticle> show)
{
    Console.WriteLine("Выполняем переданное действие:");
    show(article);
}

class NewsArticle
{
    public string Title { get; }
    public NewsArticle(string title) => Title = title;
}
```

### Ожидаемый вывод

```text
УрФУ: библиотека
УрФУ: библиотека
Выполняем переданное действие:
УрФУ: библиотека
```

### Что объяснить

Делегат хранит вызываемое действие с определённой сигнатурой. `Action<NewsArticle>` принимает новость и возвращает `void`; `Func<NewsArticle, string>` принимает новость и возвращает строку. Последний параметр типа у `Func` описывает результат.

`n => ...` — лямбда-выражение. По контексту компилятор понимает, что `n` имеет тип `NewsArticle`. Запись лямбды не равна её немедленному выполнению. Когда действие передано в другой метод, этот метод может вызвать его позже.

**Вопрос:** что выведет одно только присваивание в `showTitle`? **Ответ:** ничего; тело выполняется при вызове делегата.

## 08. Event: подписка, уведомление и отписка

**Время:** 46–56 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=14|14]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Показать, кто публикует событие, кто подписывается и когда выполняется обработчик.

### Действия преподавателя

1. Найти объявление `event Action<NewsArticle>? TitleChanged` и объяснить сигнатуру обработчика.
2. Поставить точки останова на `+=`, присваивание `Title`, `?.Invoke(this)` и тело `handler`. Выполнить первое переименование шагами.
3. Сопоставить консоль: «До изменения», затем «Событие», затем «После изменения». Уведомление происходит внутри вызова `RenameTitle`.
4. Выполнить повторное переименование с пробелами. После `Trim` заголовок не меняется, поэтому обработчик не вызывается.
5. Выполнить `-=` и новое переименование. Состояние изменится, но уведомления этому обработчику больше нет.
6. По очереди раскомментировать запрещённые внешние операции с событием, прочитать ошибки компиляции и вернуть комментарии.

### Готовый пример

```csharp
#nullable enable
using System;

var article = new NewsArticle("УрФУ: библиотека");
// Сохраняем делегат: эта же переменная потребуется для отписки.
Action<NewsArticle> handler = n => Console.WriteLine($"Событие: {n.Title}");
article.TitleChanged += handler;

Console.WriteLine("До изменения");
article.RenameTitle("Новый зал");
Console.WriteLine("После изменения"); // Обработчик уже выполнился внутри RenameTitle.

Console.WriteLine("Повторяем тот же заголовок");
article.RenameTitle("  Новый зал  "); // После Trim текст тот же: события не будет.

article.TitleChanged -= handler;
article.RenameTitle("Другой зал");
Console.WriteLine($"После отписки: {article.Title}");
// article.TitleChanged?.Invoke(article); // Ошибка: снаружи событие вызвать нельзя.
// article.TitleChanged = handler; // Ошибка: снаружи нельзя заменить всех подписчиков.

class NewsArticle
{
    public string Title { get; private set; } = string.Empty;
    // ? учитывает отсутствие подписчиков; event разрешает извне только += и -=.
    public event Action<NewsArticle>? TitleChanged;
    public NewsArticle(string title) => RenameTitle(title);

    public void RenameTitle(string title)
    {
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("Нужен заголовок", nameof(title));
        string newTitle = title.Trim();
        if (Title == newTitle) return;

        Title = newTitle; // Сначала меняем состояние, затем сообщаем подписчикам.
        TitleChanged?.Invoke(this); // Без подписчиков вызов просто пропускается.
    }
}
```

### Ожидаемый вывод

```text
До изменения
Событие: Новый зал
После изменения
Повторяем тот же заголовок
После отписки: Другой зал
```

### Что объяснить

`NewsArticle` публикует событие, а внешний код добавляет обработчик. В данном объявлении `event` оставляет подписчику операции `+=` и `-=`. Публиковать событие через `Invoke` может сам объявивший его класс. `?.Invoke` пропускает вызов, когда подписчиков нет.

Для отписки сохраняем тот же делегат. Похожая новая лямбда в `-=` не является надёжным способом снять прежнюю подписку. Если источник живёт дольше подписчика, забытая подписка может удерживать подписчика в памяти.

Обработчик здесь синхронный: вызывающий код продолжится после него. `event` сам по себе не создаёт поток и не запускает фоновую операцию. Несколько подписчиков получат уведомление по порядку добавления, пока обработчики завершаются нормально. Исключение из обработчика может прервать этот вызов; изменение `Title` к тому моменту уже произошло.

**Небольшая правка:** подписать `handler` второй раз. При следующем изменении он сработает дважды; один `-=` удаляет одно добавление. После показа вернуть исходную подписку.

**Вопрос:** после отписки заголовок перестал меняться? **Ответ:** нет, изменилась только подписка; `RenameTitle` продолжает работать.

## 09. Task и получение результата через await

**Время:** 56–66 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=15|15]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=16|16]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=17|17]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Проследить вызов async-метода, получение Task и извлечение результата через await.

### Действия преподавателя

1. Перед запуском предложить назвать порядок четырёх пронумерованных сообщений.
2. Поставить breakpoint на вызов `LoadTitleAsync` и зайти в метод. Первая строка его тела выполняется до возврата вызывающему коду.
3. Дойти до `await Task.Delay(500)`. Затем показать переменную `loading`: это задача, а не строка с заголовком.
4. Выполнить `string title = await loading` и показать, что дальше код работает с `string`.
5. Указать на `IsCompletedSuccessfully` после успешного `await`. До ожидания состояние не выводим: оно зависит от времени и остановок отладчика.

### Готовый пример

```csharp
using System;
using System.Threading.Tasks;

Console.WriteLine("1. Вызываем загрузку");
// Вызов уже начинает работу метода; await ниже не является командой «запустить».
Task<string> loading = LoadTitleAsync();
Console.WriteLine("3. Вызов вернул Task<string>");

// Если задача не готова, продолжение приостановится без блокирующего ожидания потока.
string title = await loading;
Console.WriteLine($"4. Получен результат: {title}");
Console.WriteLine($"Успешно завершена: {loading.IsCompletedSuccessfully}");

static async Task<string> LoadTitleAsync()
{
    Console.WriteLine("2. Метод начал работу");
    await Task.Delay(500); // Имитируем ожидание; HTTP-запроса здесь нет.
    return "УрФУ: библиотека"; // Возвращаем строку, которая станет результатом Task<string>.
}
```

### Ожидаемый вывод

```text
1. Вызываем загрузку
2. Метод начал работу
3. Вызов вернул Task<string>
4. Получен результат: УрФУ: библиотека
Успешно завершена: True
```

### Что объяснить

`Task<string>` представляет операцию, результатом которой станет строка. Вызов `LoadTitleAsync()` начинает выполнение метода; `await loading` получает его результат или ждёт завершения, если оно ещё не наступило.

`async` разрешает `await` в теле, но не переносит весь метод в новый поток. При ожидании незавершённой операции продолжение метода приостанавливается; это не блокирующее ожидание потока. Готовая задача может быть обработана без приостановки.

Здесь `Task.Delay` имитирует ожидание. Консольный вывод позволяет увидеть последовательность и тип результата, но не демонстрирует отзывчивость UI. Время 500 мс не является точным обещанием длительности: отладчик и планировщик влияют на наблюдаемый интервал.

**Небольшая правка:** заменить `Task.Delay(500)` на `Task.Delay(0)`. Порядок сообщений сохранится, но ожидание может не приостановить метод: задача уже готова.

**Вопрос:** нужно ли вызывать `loading.Start()`? **Ответ:** нет; в этом примере операция уже начата вызовом асинхронного метода.

## 10. Task без результата и обработка ошибки

**Время:** 66–71 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=16|16]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=17|17]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=25|25]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Показать Task без возвращаемого значения и перехват ошибки после await.

### Действия преподавателя

1. Сравнить сигнатуру `RefreshAsync` с предыдущим `Task<string>`: теперь нет значения, которое можно присвоить строке.
2. Поставить breakpoint на `throw` и на `catch`. Пройти задержку, учебную ошибку и её обработку.
3. Показать, что сообщение «Обновление завершено» пропущено, а строка после `catch` выполняется.
4. Временно закомментировать `throw`, запустить успешный вариант и вернуть исходный код. Теперь будет сообщение об успешном обновлении.

### Готовый пример

```csharp
using System;
using System.Threading.Tasks;

try
{
    Console.WriteLine("Обновляем ленту...");
    // Task не содержит значения: await здесь означает ожидание завершения.
    await RefreshAsync();
    Console.WriteLine("Обновление завершено"); // При показанном сбое сюда не попадём.
}
catch (InvalidOperationException exception)
{
    // await передаёт ошибку операции обычному try/catch вызывающего кода.
    Console.WriteLine($"Не удалось обновить: {exception.Message}");
}
Console.WriteLine("Программа продолжает работу");

static async Task RefreshAsync()
{
    await Task.Delay(100);
    // Учебный сбой после ожидания: позволяет воспроизвести ошибку без сервера.
    throw new InvalidOperationException("источник временно недоступен");
}
```

### Ожидаемый вывод

```text
Обновляем ленту...
Не удалось обновить: источник временно недоступен
Программа продолжает работу
```

### Что объяснить

`Task` без параметра типа описывает завершение операции без отдельного результата. Успех, ошибка и отмена — разные исходы задачи; здесь намеренно показана ошибка.

Исключение из асинхронного метода сохраняется в задаче и становится видимым вызывающему коду при `await`. Поэтому операция ожидается внутри `try`, а подходящий `catch` выполняет понятную реакцию. Пустой `catch`, скрывающий все ошибки, здесь не нужен.

Это дополнение к слайдам про `Task`, связанное с будущим разделом исключений. Не заменять `await` на `.Result` или `.Wait()`: это блокирующие способы ожидания, особенно нежелательные в UI. `Task.Run`, отмену, параллельные загрузки и диспетчер UI оставляем подробной лекции об асинхронности.

**Вопрос:** можно ли написать `string result = await RefreshAsync()`? **Ответ:** нет, у `Task` в этой сигнатуре нет строкового результата.

## 11. Коллекции и LINQ

**Время:** 71–78 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=18|18]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=19|19]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=20|20]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Пройти список объектов и получить выбранные заголовки через LINQ.

### Действия преподавателя

1. Показать `List<NewsArticle>` и обход `foreach`. Сравнить список объектов с массивом строк из начала занятия.
2. До запуска цепочки предсказать, сколько новостей останется после `Where`.
3. Прочитать `Where`, `OrderBy`, `Select`, `ToList` слева направо. В отладчике посмотреть результат после `ToList`.
4. Сравнить `titles.Count` и `news.Count`: фильтр не удалял элементы из исходного списка.

### Готовый пример

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

var news = new List<NewsArticle>
{
    new NewsArticle("УрФУ: лаборатория"),
    new NewsArticle("Новости города"),
    new NewsArticle("УрФУ: библиотека")
};

foreach (NewsArticle article in news)
    Console.WriteLine(article.Title);

// Where отбирает объекты, OrderBy задаёт порядок, Select получает строки.
var titles = news
    .Where(n => n.Title.Contains("УрФУ", StringComparison.Ordinal))
    .OrderBy(n => n.Title, StringComparer.Ordinal)
    .Select(n => n.Title)
    .ToList(); // Выполняем запрос сейчас и сохраняем результат в отдельном списке.

Console.WriteLine($"Найдено: {titles.Count}");
Console.WriteLine(string.Join(", ", titles));
Console.WriteLine($"Исходных новостей: {news.Count}");

class NewsArticle
{
    public string Title { get; }
    public NewsArticle(string title) => Title = title;
}
```

### Ожидаемый вывод

```text
УрФУ: лаборатория
Новости города
УрФУ: библиотека
Найдено: 2
УрФУ: библиотека, УрФУ: лаборатория
Исходных новостей: 3
```

### Что объяснить

`List<T>` хранит элементы одного указанного типа. Здесь это ссылки на объекты новостей. LINQ описывает, какие данные выбрать и в какую форму их преобразовать.

`Where` отбирает новости, `OrderBy` сортирует результат, `Select` получает заголовки. Эти операции над списком не меняют исходный список. `ToList` выполняет запрос и материализует результат; без него многие LINQ-операции остаются отложенными до перечисления.

Для сравнения заголовков явно указаны `Ordinal` и `StringComparer.Ordinal`, чтобы пример имел одинаковое правило сравнения на разных машинах. Это технический порядок, а не локализованная сортировка для готового интерфейса. Поиск учитывает регистр.

Новый список не означает глубокого копирования элементов. В этом примере выбраны строки; если сохранить `NewsArticle`, ссылки могут вести на прежние объекты.

**Вопрос:** почему в исходном списке всё ещё три новости? **Ответ:** `Where` сформировал выборку, но не удалял элементы из `news`.

## 12. Интерфейс и асинхронный источник данных

**Время:** 78–85 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=21|21]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=22|22]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Связать интерфейс источника, асинхронный метод и список объектов.

### Действия преподавателя

1. Начать с `INewsSource`: прочитать сигнатуру снаружи внутрь — задача, затем список, затем тип новости.
2. Показать строку `INewsSource source = new DemoNewsSource()`. Слева контракт, справа выбранная реализация.
3. Зайти в `LoadNewsAsync`, показать задержку и создание трёх объектов.
4. После `await` посмотреть обычный `List<NewsArticle>` и пройти его циклом.
5. Обсудить, какую строку пришлось бы заменить для другого источника с тем же контрактом. Сам вызов `LoadNewsAsync` и обход списка сохранятся.

### Готовый пример

```csharp
using System;
using System.Collections.Generic;
using System.Threading.Tasks;

// Вызывающий код зависит от контракта, а не от конкретного способа загрузки.
INewsSource source = new DemoNewsSource();
Console.WriteLine("Загружаем новости...");
List<NewsArticle> news = await source.LoadNewsAsync();
Console.WriteLine($"Получено: {news.Count}");
foreach (NewsArticle article in news)
    Console.WriteLine(article.Title);

interface INewsSource
{
    // После await результатом Task<List<NewsArticle>> станет обычный список.
    Task<List<NewsArticle>> LoadNewsAsync();
}

class DemoNewsSource : INewsSource
{
    public async Task<List<NewsArticle>> LoadNewsAsync()
    {
        await Task.Delay(300); // Локальные учебные данные: сеть не нужна.
        return new List<NewsArticle>
        {
            new NewsArticle("УрФУ: библиотека"),
            new NewsArticle("Новости города"),
            new NewsArticle("УрФУ: лаборатория")
        };
    }
}

class NewsArticle
{
    public string Title { get; }
    public NewsArticle(string title) => Title = title;
}
```

### Ожидаемый вывод

```text
Загружаем новости...
Получено: 3
УрФУ: библиотека
Новости города
УрФУ: лаборатория
```

### Что объяснить

Интерфейс описывает требуемое поведение. `DemoNewsSource` предоставляет его конкретную реализацию, а вызывающий код обращается через `INewsSource`.

После успешного `await` переменная `news` содержит обычный список. В этой реализации каждый вызов создаёт новый список и новые объекты; это поведение реализации, а не автоматическая гарантия интерфейса.

Задержка и данные локальные. Тот же контракт в дальнейшем может быть реализован источником с HTTP-запросом, но сам интерфейс сеть не включает. Как и в лекции, здесь используется `Task<List<NewsArticle>>`, чтобы закрепить уже знакомые типы.

**Вопрос:** обязан ли каждый источник ждать 300 мс? **Ответ:** нет; это свойство учебной реализации, а не требование `INewsSource`.

## 13. Проверка ввода и защита метода

**Время:** 85–88 мин. **Слайды:** [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=23|23]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=24|24]] · [[УРФУ/Курс мобильной разработки 2026/02. Основы CSharp/Презентация.pdf#page=25|25]].

**Пример:** полный блок для отдельного запуска в `Program.cs`.

**Задача показа:** Разделить проверку пользовательской строки и защиту метода от неверного аргумента.

### Действия преподавателя

1. Показать три фиксированных входа: слово, ноль и положительное число. Для каждого назвать, какая проверка пройдёт.
2. Поставить breakpoint на `continue`: неверная строка не доходит до получения анонса.
3. Затем вызвать `GetPreview` напрямую с нулём и показать переход в `catch`.
4. При наличии времени заменить фиксированный ввод на `Console.ReadLine`. Напомнить, что `null` означает конец входного потока; интерактивный вариант уже есть в материалах лекции.

### Готовый пример

```csharp
using System;

string text = "Открыт новый зал.";
// Фиксированные строки делают показ воспроизводимым без ручного ввода.
foreach (string input in new[] { "двенадцать", "0", "12" })
{
    // || проверит правую часть, только если TryParse завершился успешно.
    if (!int.TryParse(input, out int length) || length <= 0)
    {
        Console.WriteLine($"Ввод «{input}»: нужно целое число больше нуля");
        continue;
    }
    Console.WriteLine($"Анонс: {GetPreview(text, length)}");
}

try
{
    // Даже если вызывающий код обошёл проверку ввода, метод защищает своё правило.
    Console.WriteLine(GetPreview(text, 0));
}
catch (ArgumentOutOfRangeException)
{
    Console.WriteLine("Метод отклонил нулевую длину");
}
Console.WriteLine("После обработки ошибки работа продолжается");

static string GetPreview(string text, int maxLength)
{
    if (maxLength <= 0)
        throw new ArgumentOutOfRangeException(nameof(maxLength));
    return text.Substring(0, Math.Min(text.Length, maxLength));
}
```

### Ожидаемый вывод

```text
Ввод «двенадцать»: нужно целое число больше нуля
Ввод «0»: нужно целое число больше нуля
Анонс: Открыт новый
Метод отклонил нулевую длину
После обработки ошибки работа продолжается
```

### Что объяснить

`TryParse` проверяет возможность разбора строки. Условие `length <= 0` проверяет правило предметной области. `||` использует короткое замыкание: если разбор не удался, вторую часть уже не нужно вычислять.

Метод дополнительно проверяет свой аргумент, потому что его могут вызвать из другого места. В этом независимом примере `GetPreview` записан как локальная функция; в основной модели лекции он является методом `NewsArticle`. Правило положительной длины одинаково.

После обработки ожидаемого исключения программа продолжает работу. Это не означает, что ошибочный вызов всё же вернул корректный анонс.

**Вопрос:** нужна ли проверка внутри метода, если ввод уже проверен? **Ответ:** да; остальные вызывающие участки тоже должны соблюдать его контракт.

| Вопрос | event в примере | Task в примере |
|---|---|---|
| Что описывает | Уведомление источника заинтересованным подписчикам | Завершение отдельной операции |

## Точность формулировок для преподавателя

- `var` — вывод статического типа, а не динамическая переменная и не запрет переприсваивания.
- `NewsArticle?` для ссылочного типа — аннотация nullable-анализа. Постфиксный `!` подавляет предупреждение, но не защищает от `NullReferenceException`.
- Числовое преобразование, разбор строки и приведение ссылки решают разные задачи.
- Метод с `virtual`/`override` выбирается по фактическому объекту. Приведение ссылки не создаёт объект другого класса.
- Подписка на `event` не запускает обработчик немедленно. Синхронный вызов события не становится асинхронным автоматически.
- Для методов асинхронных операций использовать `Task`/`Task<T>`. Не превращать `Action` в `async void` ради этого показа: у вызывающего кода не будет задачи для ожидания. Специфику асинхронных обработчиков UI разберём отдельно.
- `Task` не является синонимом потока; `await` ожидает операцию и получает её результат. `Task.Delay` имитирует ожидание, а не выполняет запрос к серверу.
- Исключение из синхронного обработчика события и ошибка асинхронной операции имеют разные пути до вызывающего кода: обычный стек вызова и наблюдение задачи через `await`.
- `ToList` создаёт список результатов, но не обещает глубокого копирования объектов.
